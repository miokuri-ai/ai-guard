# 型5: 役割の定義ファイルに入れる「共通の節」

使い方: Claude Code のサブエージェント(.claude/agents/<役>.md)など、仕事を受けて手を動かす役の定義に、この節をそのまま入れる。規則を作る役(指示役)の手元にだけ規則を置かず、**手を動かす役の手元に届ける**ためのもの。

置いたら、指示役の側の「毎回、発注の仕様に書き写す」規則は、この節への参照に置き換える(同じ規則を2か所で管理しない)。

{ } の中は、自分の環境に合わせて書き換える。規則は自分の事故から足し、そのたびに「仕組みにできないか」を先に考える。

---

```markdown
## 全役共通の決まり(この節は全員同じ。変えるときは全員分を同時に変える)

### メモリ
- 計算は、メモリの上限をかけて起動する: `~/ai-guard/files/capped <GB> python3 ...`(例: `~/ai-guard/files/capped 8 python3 train.py`)
  - capped が「使えない」と止まる環境(systemd が無効の WSL など)では、プログラムの先頭で `memguard.require_limit_or_watch(max_gb=<GB>, watch_gb=<想定GB>)` を使う
  - 「軽い下調べ」「1行だけのプログラム」も同じ。重いか軽いかを自分で判断しない
- 計算を始める前に、想定のメモリ(GB)を書く。計算の中で `memguard.watch_rss(<想定GB>)` を使い(`sys.path.insert(0, os.path.expanduser("~/ai-guard/files"))` のあと `import memguard`)、想定を超えたら**待たずに止めて報告する**
- 計算を並列にするときは、本数 × 1本あたりの実測メモリを報告し、許された予算に収める

### ファイルを探す・近道を作る
- ファイルの探索は `safe_find.find_files` を使う(memguard と同じく `~/ai-guard/files` から import する)。`glob('**', recursive=True)` は使わない(フォルダの輪で暴走する)
- シンボリックリンクは `safe_find.safe_symlink` で作る。作業用の写しは、ほかの役が探し回るフォルダ({例: data/})の外に置く

### 報告
- 確かめていないことを「確認した」と書かない。数字・件数・表は、実物(ファイル・ログ)から取った値だけを書き、どこから取ったか(ファイル名と行)を添える
- 一部だけ確かめたときは、確かめた範囲と、確かめていない範囲を分けて書く
- 結果が想定から大きく外れたら(良すぎる・多すぎる・速すぎる)、報告の前に自分を疑う
- 採用するかどうかは書かない(人間が決める)

### 正本
- {正本のファイル名: 例 BOARD.md / LEDGER.md} を、まるごと置き換える道具(Write)で書かない。書き足しは別のファイルへ
```

---

役ごとに足すもの(例):
- **検証役**: 答え合わせ用のデータは `holdout_guard` を通してだけ開く。探す・選ぶ段階では `assert_before` を必ず通す
- **実装役**: 複数の計算をまとめて起動するときは、親のプロセスごと上限で包み、子に引き継がせる
- **監査役**: 点検した範囲と、点検していない範囲を分けて書く。正本は読むだけ
- **デバッグ役**: 原因を特定したと書くときは、根拠(ログの行・プロセスの記録・再現)を添える
